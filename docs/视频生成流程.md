# 视频生成流程（我是怎么做出那条片子的）

- 目的：把"一张图 → 一条带声音的视频"的完整脉络写下来，**换个人照着能重跑**
- 与「工具改动记录」分开：这份只讲**流程与判断**，不讲代码改了什么
- 实测环境：ComfyUI 0.44.0 / RTX 5060 Ti 8GB / H3 权重约 50GB

---

## 第 0 步：把图放进去

ComfyUI 只能读 `ComfyUI/input/`。

```powershell
Copy-Item "你的图.png" "<COMFY_ROOT>\input\whale_a.png"
```

**判断点**：图是"单人干净立绘"还是"多人物设定图"？
- 单人 → 直接用
- 多人物 → **先裁出单个**再当参考图。整张设定图丢进去，生成的视频里会同时出现多个人物

---

## 第 1 步：写提示词（六段式）

模板见 `prompts/h3-r2v-提示词格式.md`，实测有效的写法：

```
subject_definitions:
<Picture 1> is the reference character: 发色/头饰/服装/尾巴 逐项写清
<Subject 1> is exactly the girl in <Picture 1>: 同一个人，仅 <Picture 1> 里的样子
            她有且只有两只手，每个手一次只拿一样东西，放下再拿下一个

summary:
[reference generation] 五秒做菜片段：她切菜/下锅/装盘

retention_analysis:
<Picture 1> (identity anchor): fully_preserved - 脸/发色/头饰/裙/围裙/尾巴 全保留
<Subject 1>（每一帧都在）: fully_preserved - 只有手臂、手、头、表情在动

detailed_description:
[Shot 1] 景别 + 机位（**写死不移动**）+ 动作 + 手分工 + 完成度 + 表情
         嘴始终闭着：不说话、不唱歌、没有口型、下巴不动

overall_soundscape:
逐条声音事件（锅铲声/油爆声/碗落声），并声明"没有对白、没有音乐"

non_diegetic_music:
None.（音乐后期加）
```

### 这一步最容易错的三点（都是实测踩的）

| 错误写法 | 后果 | 正确写法 |
|---|---|---|
| `she chops vegetables` | **端着刀不动**（帧间差分只有 2.14） | `the knife rises high and comes down fast, over and over; the vegetables visibly shrink into small cubes` |
| `no tail on head`（负向） | **尾巴整个消失** | 正向写位置：`whale tail emerging from behind her hips, pointing down and to one side` |
| 不写"嘴闭着" | 可能出现莫名的中文口型/说话 | 每镜都写 `mouth stays closed: no talking, no singing, no lip movement` |

**核心规律：状态词（"她在切菜"）驱动不了动作，必须写"什么在怎么动、变化到什么程度"。**

## 第 2 步：校验提示词（30 秒，别省）

```powershell
node tools/prompt-lint.mjs .cache/prompt-cook-a.txt --seconds=5 --images=1
```

会查：六段是否齐、`<Picture n>` 引用是否闭合、`[Shot n]` 编号、时间码、每镜有没有手分工、帧数是否 5+17k、字数密度。

实测：黑鹤派样本 100 分；故意写坏的样本 6 分并报出 1 错误 / 11 警告 / 8 提示。

---

## 第 3 步：决定走哪条链

| 情形 | 走哪条 | 代价 |
|---|---|---|
| 只要 5 秒 | 单遍 i2v | 124 帧 @1216×704 ≈ 9.5 分钟 |
| **要 5–15 秒、要清晰** | **二采（推荐）** | 5s ≈ 5 分钟；15s ≈ 13.5 分钟 |
| 要 3 分钟 | 二采出一条闭环，再循环/倒放铺满 | 片段 13.5 分钟 + 合成 1 分钟 |

---

## 第 4 步：跑二采（本次实际用的）

```powershell
node tools/h3.mjs 2pass .cache/cfg-cook-a.json
```

一次调用内部做了**五件事**：

1. **一采**：r2v，608×352，**12 步跑满**（关键：不能只跑一半）
2. **放大**：`MinimaxH3LatentUpscaler3D` 把视频 latent ×2 → 1216×704，**音频 latent 原样穿过**
3. **二采**：`MMH3UltimateUpscale`，用**一条独立的** `BasicScheduler(steps=4, denoise=0.35)` 分块重采样（153 帧一块 / 17 帧重叠）
4. **解码**：`VAEDecode` + `VAEDecodeAudio`
5. **混流**：`VHS_VideoCombine` 出 h264 mp4

### 为什么不能照抄网上的"12 步拆 8/4"

我按参考工作流原样复现过（一采只跑 8 步，二采吃剩下的 4 步），**出的是碎片**，还把参考图上的文字糊进了画面。

四组对照后确认：**学习型 3D 放大网络只能吃跑满的干净 latent**。喂 σ≈0.6 的半成品，它只会放大噪声。

正确配方：**一采跑满 steps → 放大 → 二采用独立短曲线**。这一条价值最大。

## 第 5 步：检查（不看就发出去，必翻车）

```powershell
node tools/review-videos.mjs <视频...> --times=1,3,5
```

输出：
- **指标**：帧间差分（越小越稳）、黑帧段、强切点、音量、时长分辨率
- **抽帧联络表**：一行一条视频，一列一个时间点

### 判断标准（实测出来的）

| 指标 | 含义 | 参考值 |
|---|---|---|
| 帧间差分 < 3 | 画面基本不动 | 5s 短片应在 **4–7**；低于 2 说明**动作没发生** |
| 黑帧段 > 0 且不在片尾 | 出错了 | 片尾淡出例外 |
| 强切点 > 0 | 画面自己在跳 | 单镜应该为 0 |
| 音量 < −35dB | 几乎没有声音 | 厨房场景应在 −25 左右 |

**这次切菜第一版就是帧间差分 2.14** → 判断为"端着刀不动" → 改提示词重跑 → 4.27，菜被切成丁。

## 第 6 步：多条拼接 / 循环配乐（可选）

### 多条拼接

```powershell
ffmpeg -i A.mp4 -i B.mp4 -i C.mp4 `
  -filter_complex "[0:v][0:a][1:v][1:a][2:v][2:a]concat=n=3:v=1:a=1[v][a]" `
  -map "[v]" -map "[a]" -c:v libx264 -crf 17 -c:a aac -b:a 192k out.mp4
```

### 短片段铺满整首音乐

```powershell
node tools/music-video.mjs 片段.mp4 音乐.m4a 成片.mp4 --mode=palindrome --duration=183 --fade=3
```

- `palindrome` = 正放 + 倒放，**数学上必然无缝**（实测接缝 PSNR 46/42 dB，比普通相邻帧 33 dB 还平滑）
- 硬循环（`--mode=loop`）需要素材自己闭合，否则接缝会跳

**为什么用倒放而不是让模型闭合**：`last_frame` 条件实测**不能让模型回到起点**（首尾 PSNR 只有 21.4 dB，差异是整幅轻微缩放）。所以不指望模型，用倒放绕过去。

## 附：出问题时先查什么

| 症状 | 先查 | 常见原因 |
|---|---|---|
| **碎片/花屏** | 一采是不是只跑了一半 | 必须跑满 steps 再放大 |
| **画面不动** | 帧间差分是否 < 3 | 提示词写了状态词而不是动作 |
| **出现多个人物** | 参考图是不是多人设定图 | 先把参考图裁成单人 |
| **参考图的文字跑进画面** | 参考图有没有文字；IPAdapter 权重 | 裁掉文字；权重压到 0.2–0.35 |
| **奇怪的说话/唱歌** | 提示词有没有锁嘴；是否开了音频 | 每镜写 `mouth stays closed`；不想要音轨就 `audio:false` |
| **角色看着不像** | 参考图本身质量；是否多人物被平均 | 换更干净的单人参考图 |
| **卡在最后一步** | 帧数是否 > 362 | 长片必须走 2pass（分块），不要单遍 |
