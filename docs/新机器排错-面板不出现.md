# 新机器上"面板不出现"排错

> 症状：装好后界面里没有 Comfy 工作台（左栏没有入口、右下角没有按钮）。
> 这份文档的目的：**用事实判定是哪一层没起来**，而不是猜。

## 第 0 步（最省事）：打开一个网址，把整页复制过来

Host 半会挂一个自检页。它**不依赖浏览器那半渲染成功**，所以面板完全不出现时也能用：

```
http://127.0.0.1:<DSH 实际端口>/comfy-live/health
```

端口每次启动会变，从 DSH 窗口地址栏取。页面上是一段 JSON，包含：

| 字段 | 看什么 |
|---|---|
| `paths` | `projectRoot` / `comfyRoot` 解析到哪；`projectRootIgnored` 非空说明配置里写了别的机器的路径 |
| `client.inSync` | **必须是 true**。false = 浏览器跑的是旧 bundle，`node build-client.mjs` 后刷新 |
| `clientDiag` | 浏览器那半写回来的最后 30 行。**空数组 = 客户端一次都没跑起来** |
| `host` | Host 半的状态、跑了多少次执行、连了几个面板 |
| `comfy` | ComfyUI 通不通、版本、显存 |

**一条判据就能定位**：`clientDiag` 为空 → 客户端 bundle 没加载（装/入口/版本问题）；
有 `slot.fail` → slot 名和那台机器的 DSH 版本对不上。

## 后面的步骤（health 页拿不到时才用）

## 三层结构（必须先分清坏在哪一层）

| 层 | 怎么算"起来了" | 判据 |
|---|---|---|
| Host 半 | DSH 的 HTTP 上挂了 `/comfy-live/*` | `GET /comfy-live/api/state` 返回 `{"ok":true,...}` |
| Client 半 | 浏览器加载了 `client.js` 并执行了 `apply()` | `.cache/client-diag.log` 里有一行 `[apply]` |
| 入口 | 至少一个 slot 注册成功 | 日志里有 `[slot.ok]`（每个入口一行） |

## 第一步：Host 起来了吗

在装 DSH 的那台机器上（端口每次启动都会变，从窗口地址栏或 `netstat` 取）：

```powershell
# 端口示例：把 63584 换成实际的
curl.exe -s http://127.0.0.1:63584/comfy-live/api/state
```

- 返回 JSON → Host 正常，进第二步
- 404 / 连不上 → Host 半没加载。查 DSH 的插件列表里有没有 `@local/dsh-comfy-live`；
  没装 → 装；装了但仍 404 → 看 DSH 启动日志里这个插件的报错（多半是 `webServer` 服务没拿到）

## 第二步：Client 起来了吗

```powershell
# 插件写的是 <projectRoot>\.cache\client-diag.log（不是 runs\）
Get-Content "<插件目录>\..\.cache\client-diag.log" -Tail 30
```

或者干脆不用文件：打开 `http://127.0.0.1:<端口>/comfy-live/api/diag`，
它返回同一份日志的 JSON。

日志里的关键行：

| 日志 | 含义 | 结论 |
|---|---|---|
| `[apply] {"slots":true,...}` | 客户端跑了 | 进第三步 |
| `[slot.ok] {"slot":"sidebar.panellist"}` | 左栏入口注册成功 | 应该有入口 |
| `[slot.fail]` / `[slot.skip]` | 这个 slot 名字在对方 DSH 上不存在 | **版本不匹配**：记录 slot 名，按对方名字改 |
| 完全没有 `[apply]` | `client.js` 根本没被加载 | 见下面"最常见的原因" |

## 第三步：一个入口都没注册上怎么办

`[apply.done] {"registered":0,...}` 说明 `apply` 跑了但三个 slot 全失败。
这一定是 **DSH 版本差异**（slot 名变了）。把这一行日志发给维护者，
里面已经带了失败原因（`no-slots` / 具体异常信息）。

---

## 最常见的原因（按概率排）

1. **装的是 MCP 那个包，不是 DSH 客户端插件**
   仓库里是两个东西：
   - `mcp/server.mjs`：给 AI 用的工具（npm 包）
   - `dsh-plugin/`：界面面板（DSH 客户端插件）
   只装前者，界面里不会有任何东西。

2. **插件目录没被 link 进 DSH profile**
   本机是这样接的（见 profile 的 `package.json`）：
   ```json
   "@local/dsh-comfy-live": "link:D:/dev/ComfyForge/dsh-plugin"
   ```
   换机器要改成那台机器上的实际路径，然后 `pnpm install` 让链接生效。

3. **DSH 版本比插件新，客户端 bundle API 变了**
   本插件的 `client.js` 用 `window.__ModuleLoader__.load({ id, factory })`。
   如果对方的 DSH 改了这个入口，`client.js` 会被静默忽略 —— 日志里连 `[apply]` 都没有。
   判定方法：`GET /comfy-live/api/state` 正常、但日志里没有 `[apply]`，基本就是这条。

4. **路径写死在配置里**
   `cordis.patch.yml` 现在**故意不写绝对路径**，全部自动探测。
   如果谁手动填了 `comfyRoot` / `projectRoot` 且路径在对方机器上不存在，
   会表现成"面板起来但全是空的"（不是"面板不出现"）。

## 官方口径：装上了 ≠ 生效了（三道关卡）

依据 `@deepseek-ai/dsh-client-modules` 的 README 与 DSH 插件注册表的排错指南：
一个包要真正生效，必须**同时**满足三条：

1. pnpm 把它装进了**你实际启动的那个 profile**（profile 之间互不相通）；
2. `package.json` 里声明了 `dsh.bundle.patch`，DSH 才会把它当成 bundle 层加进来；
3. **重启**那个 profile 之后，组合（compose）没有报错，客户端 bundle 才会被 `/plugins` 服务出去。

> 注意第 3 条：bundle 成员是**启动边界**。浏览器刷新、只更新文件都不算；
> 必须停掉旧进程、重新启动同一个 profile。

### 官方给的判定顺序（照这个顺序做，一步一收敛）

```powershell
# 0) 用你实际启动的那个 profile 名（桌面版一般是 desktop，网页版一般是 web）
dsh plugin --profile desktop list --depth 0

# 1) 包在不在这个 profile 里
#    没有 → 安装问题；有 → 继续

# 2) DSH 有没有把它当成 bundle 层加进来
dsh --profile desktop --dump-config | Select-String -Pattern "comfy"

# 3) 有输出 → 层加上了；没输出 → bundle 没被识别（见下面"两条硬要求"）

# 4) 重启同一个 profile（不是刷新浏览器）
#    桌面版：退出应用再打开；网页版：停掉旧进程后 dsh web --no-open
```

### 两条硬要求（缺一条就是"面板不出现"）

| 要求 | 我们的现状 | 怎么查 |
|---|---|---|
| `package.json` 里有 `dsh.bundle.patch` | **有**，指向 `./cordis.patch.yml` | 看文件 |
| `package.json` 的 `exports["./client"]` 指向存在的文件 | **有**，`./client.js` | 看文件；文件缺了 DSH 只会打印一条构建提示，界面静默无面板 |

### 一个容易误判的现象

DSH 的客户端 bundle 由 Node 半扫描 `dsh.client` 包、按 `exports["./client"]` 解析、
构建后挂在 `/plugins` 下提供。**如果这个文件缺了，DSH 不会报"面板缺失"，
只在启动输出里给一条构建提示** —— 界面上就是干干净净什么都没有，浮窗也不会有。
所以"连浮窗都没有"这条症状，最可能指向：**客户端 bundle 没被加载**，不是我的入口写错了。



- `apply()` 里每个 slot 注册都单独 try/catch，**任何一处失败都不会让整个插件挂掉**；
  失败原因写进 `client-diag.log`（`slot.fail` / `slot.skip` / `apply.done{registered}`）。
- 诊断日志写不回 Host 时，会在浏览器内存留一份，并 `console.warn` 提示。
- 配置里不写死任何绝对路径（见 `cordis.patch.yml` 顶部注释）。

## 还需要对方提供的一条信息

只要拿到 **`.cache/client-diag.log` 里 `[apply]` 那几行**（有或没有都要说），
就能立刻判定是"没装"还是"版本不匹配"，不用再猜。
