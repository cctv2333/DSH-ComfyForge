# 造图与局部编辑：我现在能做什么

一句话：**不只是「填参数重抽」，而是能读节点、写图、验证、只改一块、再验证。**

## 三层能力

### 1. 模板层（快，但受模板限制）
`comfy_run(template="flux_t2i", params={...})` —— 换提示词/尺寸/seed/步数。
适合批量试探方向。

### 2. 图构造层（能造新链路）
- `comfy_nodes(query|class_type)`：从本机 `/object_info` 查节点真实输入/输出；
- 直接写 API 格式 graph（`{id: {class_type, inputs}}`），或写进 `workflows/*.json` 当模板；
- `comfy_run` 提交前做静态校验（节点存在、必填、连线、枚举、数值范围）；
- 失败时给节点级错误 + 日志 Traceback。

这一层我用它造了两个新模板：`flux_img2img`、`flux_inpaint`（见 `workflows/`）。

### 3. 局部编辑层（改一块，不动其它）
`comfy_edit(image, box=[x,y,w,h], prompt, denoise)`：
1. 上传原图 → 2. 画蒙版（圆角矩形/椭圆 + 羽化 + 外扩）→ 3. 上传蒙版 →
4. 走 `flux_inpaint`：`VAEEncode → SetLatentNoiseMask → KSampler(denoise 0.7) → VAE → Save` →
5. 回来算三件事：产物指标、**蒙版内/外改动比例**、附回图片。

不给 `box` 就是整图 img2img（`denoise 0.25–0.45` 精修）。

## 实测（2026-11-03）

原图：`cyber/inside_00001_.png`（1344×768，车内少女）。
编辑区域：`[628, 378, 96, 196]`（香槟杯），提示词「glowing turquoise energy drink in a crystal glass」，
denoise 0.8，20 步。

结果：

| 指标 | 数值 | 说明 |
|---|---|---|
| 蒙版内改动 | 68.65% | 该区域确实被重画 |
| 蒙版外改动 | 1.06% | 基本是 VAE 重编码的整体微扰，不是重绘 |
| 蒙版外平均像素差 | 1.95/255 | 肉眼不可见 |
| 耗时 | 52.5s（1 次接力） | 1344×768，20 步 |

图片上：杯子从香槟变成发光的青绿色饮品，杯型/手/背景保持不变。

## 为什么这比「重抽」强

模型听不懂指令时，**重抽是赌博，局部编辑是手术**：
- 「手变形」→ 只框手，重画手，其它不动；
- 「招牌乱码」→ 只框招牌，换成图案或去掉文字；
- 「想加个飞行器」→ 在窗外框一块，画一个，不破坏构图；
- 每次都有 locality 数字，能判断这次改动到底有没有跑到区域外。

## 失败先归因（顺序不能反）

1. **提示词语义**：介词/关系词（on vs inside）、主体数量、视角。
2. **概念缺线索**：比如「浮空」在车内视角看不见，必须给外部线索（窗外飞行器、下方街道、无路面）。
3. **模型能力**：4bit 量化、汉字、多手指、精细机械结构。
4. **采样参数**：denoise 太高会重绘过头，太低改不动；步数 < 12 细节不足。

## 下一步能加的能力（按性价比）

1. **放大模型**（4x-UltraSharp 之类）：`upscale_models` 目前为空，补上就能「先粗后精」，也是精选流程的最后一步；
2. **FLUX Fill**（专用 inpaint 模型）：比通用 KSampler + 蒙版更听话，尤其是大面积替换；
3. **ControlNet / Depth**：用参考图控制构图（姿势、镜头、建筑线条），这是「按草图生成」的关键；
4. **区域提示词**（regional prompt）：一张图里不同区域不同描述，适合多主体。
