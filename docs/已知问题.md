# 已知问题与难处

> 这份是**给使用者看的**公开清单：哪些坑已经踩过、现在什么样、绕不过去的硬约束是什么。
> 每条都写清「现象 / 原因 / 现状」，不含本机路径与私有信息。
> 版本：0.3.0

---

## 一、已验证的硬约束（不是 bug，是能力边界）

| 边界 | 事实 | 影响 |
|---|---|---|
| 8GB 显存 | 一次只能跑一张；连发会造成显存碎片化卡死 | 必须串行；卡死后要重启 ComfyUI |
| MCP 单次调用超时 | 客户端约 60s 就把调用判超时 | 所有等待类工具都做成「等一小段 + `pending` 接力」，`wait_s` 别设 >55 |
| 画面内文字 | 出图模型基本不会写字；招牌上的字母会变成 `GXIEE`、`7ATC` 这类乱码 | 文字一律后期排版叠加，别指望模型 |
| 具体机型轮廓 | C-130 这类有明确轮廓的实物，靠提示词画不准 | 必须给参考图 + ControlNet |
| SDXL 提示词长度 | 文本编码在 **77 token（≈300–350 字符）** 处截断，且**不报错** | 长提示词的后半段等于没写；"能塞多少"≠"能听懂多少" |
| 局部编辑光照 | 新放进场景的物体，光照方向常与场景不一致（贴纸感） | 属 BUG-0010，仍未彻底解决 |

## 二、工具当前的已知缺陷

### 1. 质量指标不能跨镜头数比较（会误导选片）

`videoMetrics` 的 `flicker` 是**全部相邻帧亮度差的均值**，而镜头切换那一帧的差分天然极大。
所以「6 个镜头的片子」flicker 一定比「1 镜到底的片子」高——**这和画面稳不稳定不是一回事**。

实测：同一模型同一 seed，6 镜版本 flicker 8.40，1 镜版本 5.24，但 1 镜版本明显更差。

**现状**：`flicker` 仍会输出，但**不要用它给镜头数不同的片子排序**。计划加 `flickerNoCut`（跳过切点前后各 2 帧重算）。

### 2. 产出分拣只覆盖图片，不覆盖视频

`comfy_triage`（scan / apply / restore）能把「读不出 / 近乎纯色 / 死糊 / 过小 / 重复」的图移到 `output/_trash/` 并可恢复，
但：
- 它**只扫图片**，视频没有分拣；
- 它只判**客观缺陷**，不判「好不好看」。

**现状**：好图与垃圾图仍可能混在一个目录里；需要人工看图。

### 3. 依赖体检不校验权重体积

`preflight` / `comfy_health` 的能力清单只按**文件名正则**判断模型在不在，
采到了体积却**从不比对**。所以一个 0 字节的占位文件、或者下到 40% 的残文件，会被判为「通过」。

**现状**：可通过 + 手动核对体积。计划加「体积误差 ≤10%」判定。

### 4. 模型权重从哪来，工具没说

能力清单会告诉你「缺 H3 主模型，约 19.5GB，放进 `models/diffusion_models/`」，
但**不告诉你从哪个仓库下载**，也没有许可字段。

**现状**：需要自己找。工具的原则是**永不自动下载**。

### 5. 日志只证明「跑完了」，证明不了「跑对了」

执行成功（`status=success`）只代表节点跑完，不代表结果可用。
实测：三次质量失败的出图，日志一片干净、零错误、零警告。

**现状**：验收必须靠看图 / 看指标，不能靠日志。

### 6. 实时面板只能直播「经网关提交」的任务

ComfyUI 的 `execution_*` 事件只发给**提交时那个 client_id** 的 socket。
所以：
- 经实时台网关提交的任务：节点级直播、实时预览帧、自动把工作流写进 ComfyUI 的 workflows 目录；
- **你自己在 ComfyUI 界面里点的任务**：只能事后 8 秒轮询补进时间线，没有逐节点过程。

这不是实现取舍，是 ComfyUI 协议限制。

### 7. `ui/server.mjs` 老看板已被实时台取代

它仍可独立运行（`node ui/server.mjs` → `http://127.0.0.1:8790`），但只能读 `/history`（事后），
没有节点级直播。保留仅为兼容。

## 三、踩过的坑（已修，但值得知道）

| 坑 | 现象 | 原因 |
|---|---|---|
| 用 PowerShell 重写中文源文件 | 整份文件变乱码、正文丢 ASCII 字符 | PowerShell 按 GBK 解码 UTF-8 再写回，3 字节汉字被拆坏 |
| 用 `Get-Content` 读中文文件 | 看起来是乱码，其实文件是好的 | 同上，只是**读**；读不改文件，写才会毁文件 |
| 把 `comic` 写进负面词 | 想画漫画页，版式出不来、却冒出对话气泡 | 正向写 `comic page`，负面写 `comic`，正负互相抵消 |
| 复制参考图到 input 时带时间戳 | 同一张图被复制成十几份 | 文件名带 `Date.now()`，永远命中不了「已存在」 |
| 学习型 3D 放大网络出彩色碎片 | 二采输出全是碎片 | 把 σ≈0.6 的半成品 latent 喂给按干净 latent 统计归一化的放大网络；后续低噪声步收不回来 |

## 四、怎么报问题

带上三样东西，绝大多数问题能定位：
1. `node mcp/doctor.mjs --json` 的输出；
2. 出问题时 `comfy_health` 的返回（含能力清单与缺失项）；
3. 对应那次执行的 `runs/live/<prompt_id>.json`（含完整 API 图、产物、错误）。
