# 能力边界与依赖清单

- 日期：2026-11-04
- 一句话：**这个工具不是"装了 87GB 才能用"，而是分三层——一层只要 Node，一层要 ComfyUI，一层要 51GB 权重。三层各自能干什么、缺什么、降级成什么样，必须能被机器自己说出来。**

自查命令（任何一台电脑都能跑，不需要 ComfyUI 在运行）：

```bash
node tools/preflight.mjs          # 看本机
node tools/preflight.mjs --empty  # 模拟"什么都没有的电脑"，验证工具会不会说人话
```

## 二、三层能力

### 第 0 层：只要 Node（约 0 依赖，0 下载）

| 工具 | 能力 | 需要什么 |
|---|---|---|
| `tools/prompt-lint.mjs` | 提示词 20+ 条规则校验 | 无 |
| `videoMetrics()`（`mcp/lib/video.mjs`） | 帧间差分 / 黑帧 / 切点 / 音量 | **ffmpeg**（约 100MB） |
| `tools/music-video.mjs` | 循环铺满 + 混音 | **ffmpeg** |
| `tools/preflight.mjs` | 这台机器能干什么 | 无 |

**在别人电脑上**：装了 Node 就能跑校验器；再放一个 `ffmpeg.exe`（不用装，绿色版即可）就能跑指标和合成。**这一层是工具的最低承诺。**

### 第 1 层：要 ComfyUI（约 1–2GB 本体 + 6.5GB 一个模型）

| 工具 | 能力 | 依赖 |
|---|---|---|
| `comfy_run` / `comfy_edit` / `comfy_inpaint` 等 | 出图、局部重绘 | ComfyUI + 任意 SDXL/Illustrious checkpoint |
| `tools/character-sheet.mjs`（待建） | 三视图 | 同上 |

**没有 ComfyUI 时**：这一整层不存在。工具会给"装 ComfyUI（1–2GB）+ 一个 6.5GB 动漫底模"这一条最低路径，**不会**把 87GB 一次性推给你。

### 第 2 层：要 51GB H3 权重（视频）

| 工具 | 能力 | 额外依赖 |
|---|---|---|
| `comfy_video mode=single` | 图/文生视频（带原生音轨） | H3 主模型 19.5 + 文本编码器 25.3 + 视频 VAE 4.9 |
| `comfy_video mode=2pass` | 低清→放大→分块精修 | 再加：`ComfyUI-PlagueKind-Nodes` + `Comfyui_Minimax_h3_latent_Upscaler` 两个包 + 3D 放大权重 0.64GB |
| `tools/sweep.mjs` | 抽卡批跑 | 同 2pass |

**降级方案（工具里写死，不会假装一样）**：

- 没有二采节点包 → 只做"低清一采 + ffmpeg lanczos 放大"。**不出细节，但不花屏。**
- 没有 H3 权重 → 用 ffmpeg 对单张图做缓慢推拉（Ken Burns）。**零模型，但画面是静止的。**

## 三、工具必须遵守的四条纪律

1. **不自动下载。** 任何缺失只打印"是什么、多大、放哪个目录、哪条命令"，不替用户决定占磁盘。
2. **三态判定，不冒充确定。** ComfyUI 没连上时说"无法确认"，不说"缺"也不说"有"。
3. **降级要写进输出。** 用了降级路径就必须在结果里标出来，不能让用户以为拿到了完整效果。
4. **依赖写死在清单里，不靠记忆。** 新增能力必须同时更新 `mcp/lib/requires.mjs`，否则 `preflight` 会漏报。

## 四、这个工具**不承诺**什么

- 不承诺在没装 ComfyUI 的机器上出图/出视频。
- 不承诺没有对应权重时给出等效效果。
- 不承诺跨机器复现同一张图（seed 相同也不行：显卡、驱动、torch 版本都会影响）。
- 不承诺自动解决模型授权/下载来源问题。

## 五、实测记录（三态在三种环境下的输出）

| 环境 | 输出 |
|---|---|
| 本机（ComfyUI 在跑） | `8/8 项确认可用` |
| 本机但 ComfyUI 关掉（`COMFY_URL` 指向死端口） | `3/8 项确认可用 · 5 项无法确认` |
| 模拟空机器（`--empty`） | `3/8 项确认可用 · 5 项无法确认`，并打印最小安装路径 |

第一版 preflight 有个 bug 值得记：它只查 `PATH` 里的 ffmpeg，而本机 ffmpeg 在 `D:\vidlens\...`（工具的 `ffmpegBin()` 会回退到那里）。于是**工具把自己的可用能力误判成不可用**。已改成与真正干活的代码共用同一套解析顺序——**能力判定必须和生产逻辑同源，否则就是自欺**。
