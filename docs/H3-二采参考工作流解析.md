## 一、这张图到底在干什么（一句话）

**一采**在 608×352 上跑 12 步里的前 8 步 → **把视频 latent 用学习型 3D 放大网络 ×2 到 1216×704**（音频 latent 原样穿过）→ **二采**用同一个调度器剩下的 4 步（≈denoise 0.33）在 `MMH3UltimateUpscale` 里**按 153 帧一块、17 帧重叠**分块重采样并缝合 → 解码成 15.08s / 1216×704 / 24fps 带音轨。

这不是"低清出片再贴一张高清"，是**同一条 sigma 曲线被切成两段、中间插一次放大**，所以两遍看到的是同一个 conditioning、同一个 seed、同一套噪声来源。

## 二、逐节点事实（全部取自 JSON 连线，非推断）

### 模型链

| 节点 | 参数 | 说明 |
|---|---|---|
| `UNETLoader` | `DasiwaMinimaxH3_dasiwaHybridV2_int8.safetensors` | 与本机同一份权重 |
| `MiniMaxH3MemoryEfficientSageAttentionPatch` | **mode=4（被 bypass）** | 他没开 Sage 注意力 |

### 条件与调度

| 节点 | 参数 | 说明 |
|---|---|---|
| `MiniMaxH3ReferenceToVideo` | width/height ← `ResolutionSelector`；length ← `ComfyMathExpression`；`ref_image_size=match`；`vae` + `audio_vae` 都接；`ref_image_0` 只接 1 张（`图片-流萤Q版三视图正脸图.jpeg`），其余 5 图 / 1 视频 / 3 音频**全部 mute** | **r2v，不是 i2v** |
| `ResolutionSelector` | 16:9 / **0.2 MP** / 32 | → 608×352（其自带 MarkdownNote 给了对照表） |
| `ComfyMathExpression` | `max(5, round(a*24)) + (5-(max(5,round(a*24))%17))%17`，a=15s | → **362 帧**（=5+17×21，15.08s） |
| `BasicScheduler` | `simple` / **steps=12**（=INTConstant 8 + INTConstant 4）/ denoise 1 | 一条曲线，不是两条 |
| `SplitSigmas` | step=**8** | high → 一采；low → 二采 |

### 一采

`SamplerCustomAdvanced`（noise=RandomNoise seed `795140483442838`，guider=BasicGuider(model=上面那条链，cond=r2v.positive)，sampler=`res_multistep`，sigmas=**high_sigmas**，latent_image=r2v.LATENT）

### 二采

```
一采 latent
  └─ LTXVSeparateAVLatent ──► video_latent ──► MinimaxH3LatentUpscaler3D
  │                              (learned 3D, mode=scale by multiplier, scale=2, align=32, cuda/fp16)
  │                                       └─► LTXVConcatAVLatent ◄── audio_latent（原样）
  │                                                    └─► MMH3UltimateUpscale
  │                                                          model / conditioning(r2v.positive)
  │                                                          latent / noise(同一个 RandomNoise)
  │                                                          sampler / sigmas=low_sigmas
  │                                                          negative=ConditioningZeroOut(positive), cfg=1
  │                                                          temporal_split_param=153 / 17 / 0.99
  │                                                    └─► VAEDecode + VAEDecodeAudio
  │                                                    └─► VHS_VideoCombine（24fps, crf 19）
```

- `MMH3TemporalSplitParams` = **chunk 153 帧 / overlap 17 / anchor_strength 0.99**（153=17×9，合法值）
- 153 帧 ≈ 6.4s → 362 帧切成 **3 块**，这正是它能在 8GB 上跑 1216×704 的原因
- `MMH3UltimateUpscale` 源码（`ComfyUI-PlagueKind-Nodes\ComfyUI-H3-UltimateUpscale-LD\nodes.py:1729`）写明：分块 → 每块内放大 → 时间重锚 → **把第 0 帧 keyframe 钉成上一块重采样后的那一帧** → 采样 → 空间分块 → 缝合

## 三、三个机制，各自解决一个具体问题

| 机制 | 解决什么 | 证据 |
|---|---|---|
| sigma 拆 8/12，中间插放大 | 让二采只做"低噪声重建纹理"，不重画表演 | `SplitSigmas` step=8 + 两侧槽位连线 |
| 学习型 3D latent 放大（不是插值） | 避开 H3 那个约 5B 参数的 VAE 的"解码→放大→再编码"往返；也避开双线性插值的重影 | 3D 节点 README「省时间，不省显存」；`latent_upscale_models/` 权重 690MB |
| 153/17 时间分块 + frame-0 锚 | 8GB 显存装不下 362 帧整段重采样；分块还能消末尾帧闪烁 | 节点 tooltip + 源码；README 更新日志「启用时间分块…修复末尾帧闪烁」 |

## 四、我的复刻 vs 他的图：逐项 diff

复刻脚本：`tools/experiments/repro-2pass.mjs`

| 项 | 他的图 | 我的复刻 | 可疑度 |
|---|---|---|---|
| 条件节点 | `MiniMaxH3ReferenceToVideo`（ref_images, audio_vae 接） | `MiniMaxH3ImageToVideo`（first_frame） | **高** |
| 调度 | 12 步拆 8 / 4（二采 4 步，denoise≈0.33） | 6 步拆 4 / 2（二采 **2 步**） | **高** |
| 负条件 | `ConditioningZeroOut(positive)` → CFGGuider(cfg=1) | 未接（走 BasicGuider） | 中 |
| 模型链 | + `ModelAttentionBackend`(comfy kitchen) | 无 | 低 |
| 放大 | 3D ×2 | 3D ×2（同） | — |
| 分块 | 153 / 17 / 0.99 | 153 / 17 / 0.99（同） | — |
| 音频 | VAEDecodeAudio + 混流 | 无 | 低（不影响画面） |
| 尺寸 | 608×352 → 1216×704 | 640×384 → 1280×768 | 低 |

**为什么"i2v"最可疑（推断，待验证）**：`MMH3UltimateUpscale` 每块都会 `reanchor_conditioning(f0,f1)` 并 `anchor_conditioning`——把每块第 0 帧的 keyframe 钉到上一块的输出帧。i2v 的 conditioning 里恰好有**一帧首帧 keyframe**；分 3 块后这个 keyframe 会被反复重锚到每块开头，等于**把那张参考图硬塞进每块的第一帧**。外观正是我观察到的"碎片/旗子盖满、主体轮廓散开"。r2v 没有 keyframe，只有 refs（`normalize_minimax_refs` 会按真实 latent 重写 refs 元数据），不会踩这个坑。

**为什么"二采只剩 2 步"也致命**：`simple` 曲线在 6 步下切在 4，最后一段 sigma 只覆盖很小一段噪声等级，等于"刚放完大就立刻收尾"——这类失败通常表现为糊/脏，但叠加上面的 keyframe 错位就会一起放大。

### 需要复核的历史结论

## 七、实测结果（2026-11-04 19:15–19:30，39 帧 / 608×352 → 1216×704）

三组对照，同一张参考图、同一 prompt、同一 seed，只改一处：

| 组 | 图 | 结果 | 证据 |
|---|---|---|---|
| A 照抄参考工作流（SplitSigmas 8/12，二采吃后半段） | 24 节点 | **碎片盖满脸**，还能看到参考图上的**文字被糊进画面底部** | `comfyforge/2pass-test/r2v_00001-audio.mp4` |
| B 同一路但切成 2 块（chunk 34/17） | 同上 | **仍是碎片**，文字更清楚 | `chunk34_00001-audio.mp4` |
| C 一采**跑满** 12 步 → 放大 → 二采**独立** 4 步 denoise 0.35 | 同上 | **干净**，主体、环境、光影都对 | `refine_00001-audio.mp4` |
| D 只跑一采（跑满 12 步）解码对照 | — | **完全干净** | `pass1full_00001-audio.mp4` |

**结论（事实层面）**

1. r2v 这条链本身没问题——一采跑满 12 步直接解码，画面干净（D）。
2. `comfy kitchen attention` 这个 attention 后端也没问题（D 就是带着它跑的）。
3. 碎片是**二采这一段的输入喂错了**造成的：把 σ≈0.6 的半成品 latent 喂给学习型 3D 放大网络，再拿 4 步低噪声收尾，救不回来（A、B）。
4. 分几块**不影响**结果（B 仍旧坏）——所以不是"分块/锚点"的问题。
5. 换成"跑满 → 放大 → 独立短曲线"立刻干净（C）。

**二采到底有没有用（不是白放大）**：把 C 与"一采直接 lanczos 拉到 1216×704"逐项比：

| 指标 | 一采 lanczos | 二采输出 |
|---|---|---|
| lap_var（整图锐度） | 51.5 | **234.6** |
| lap_var_512（归一化） | 746.6 | **1403.2** |
| edge_pct | 4.02 | 5.73 |
| hf_ratio | 0.0086 | **0.0193** |

锐度 4.5 倍、高频占比翻倍——**是重建出细节，不是插值放大**。

**为什么他的图能跑而照抄不行**：未查清，标记为未知。两个可能方向：① 他停在 0.30，旧版放大节点的归一化统计不同；② 他图里 `BasicScheduler.steps` 实际没有吃到 12（线路经 `ComfyMathExpression`），若 steps=8 与 `SplitSigmas step=8` 相等，后半段 sigma 为空，等价于"跑满"。**不猜，先按实测能跑的写。**

**已固化进工具**：`comfy_video mode=2pass` / `tools/h3.mjs 2pass`，默认 `steps=12 → 放大 ×2 → refine 4 步 denoise 0.35`。参考工作流那条 SplitSigmas 路保留在 `splitSigmas: true` 分支里，注释写明"实测出碎片，别用"，只为复现失败。
